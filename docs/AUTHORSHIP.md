# Authorship and provenance

This file records who made Wind and how. It is meant to be honest and checkable. Every claim below can be checked against the git history and the GitHub issues and pull requests of `github.com/Maxaubert/Wind`.

## Author and owner

Wind is written, directed and owned by **Max Aubert** (GitHub: `Maxaubert`). He holds the copyright in Wind. The licence terms are in [LICENSE](../LICENSE).

## How Wind is made

Wind was built with AI coding assistants, mainly Claude Code, working under Max's direction. Much of the code text, and much of the documentation text, was generated by those tools. Wind does not claim otherwise.

The work follows a fixed loop:

1. **Max specifies.** He decides what Wind should do and how it should behave. He opens a GitHub issue for each feature, bug or change, describing the problem, the behaviour he wants and often the approach.
2. **The AI drafts.** An AI assistant writes a change on a branch, following Max's issue and the project rules he set in `CLAUDE.md`.
3. **Max tests on his own hardware.** Changes that affect runtime behaviour are built, signed and installed on his own PC (a 4K display at 225% scaling with an NVIDIA RTX 5090), then tried in real use: on the desktop, in games and with assistive tools.
4. **Max accepts or rejects.** He decides whether the change is right. Many drafts were sent back, reworked or reverted after his testing. A change he rejects does not ship.
5. **Merge on approval.** Every change goes through an issue and a pull request. A pull request is merged only after Max says yes to that specific pull request. His standing rules forbid merging without his explicit yes, and a yes never carries over to another pull request.

The AI tools act under Max's GitHub account. That is why his account appears as the author of the issues and pull requests and as the one who merged them. The decisions in them are his.

## Owner contributions

The AI tools wrote much of the code text. Max made the creative and technical decisions that shape Wind:

- **Design.** The concept of a lightweight fullscreen magnifier with hold-to-zoom on mouse side buttons, the original design spec and plan (2026-05-24), and the specs for later features (own renderer, configurable zoom, profiles, installer, tracking modes, tray, settings redesign).
- **Product decisions.** Which engine is the default, which engines are removed, what the defaults are, what the settings and tray show and in what order, and which behaviours are acceptable.
- **Selection and arrangement.** Choosing among the approaches the AI drafted, deciding which ones to keep, which to revert and how the features fit together into one product.
- **Testing and rejection.** Field-testing changes in real use and rejecting the ones that felt wrong, even when they passed the automated tests. Many rules in the developer docs exist because Max tested an approach and turned it down.
- **Rules and constraints.** Writing and maintaining the project rules (`CLAUDE.md`, the architecture docs) that every AI draft has to follow.

### Examples of owner decisions

Each item points to the issue or pull request where the decision is recorded.

1. **Original design.** The design spec (`a09a5ad`) and implementation plan (`eb7c838`) were committed on 2026-05-24, before any code. Later feature specs are kept in [docs/specs](specs/) and [docs/design](design/).
2. **Early engine choices.** Removing the Magnification API fallback ([#20](https://github.com/Maxaubert/Wind/issues/20)) and reverting the DirectComposition backend after it caused background-game lag ([#28](https://github.com/Maxaubert/Wind/issues/28)).
3. **Engine direction, tried and reversed.** Max had the transform engine replaced with a driver for the built-in Windows Magnifier ([#146](https://github.com/Maxaubert/Wind/issues/146)). After testing he had the transform engine revived ([#148](https://github.com/Maxaubert/Wind/issues/148)), and it later became the default on the desktop ([#272](https://github.com/Maxaubert/Wind/issues/272)).
4. **Game performance work.** The investigation into zoom stutter over games ([#148](https://github.com/Maxaubert/Wind/issues/148)) and its fix ([PR #151](https://github.com/Maxaubert/Wind/pull/151)). Several drafts were reverted along the way after field testing (for example `a0f365b`, a lazy magnification context that broke zooming in game).
5. **Write-rate and step gates rejected.** A write-rate cap and a minimum pan step were tried to match the built-in Magnifier ([#204](https://github.com/Maxaubert/Wind/issues/204)) and reverted the same day after testing: the throttled view wobbled and looked like low frame rate. The rule "do not throttle the view" is recorded in [05-transform-engine.md](architecture/05-transform-engine.md).
6. **Cursor grows with the zoom.** A constant-size cursor was rejected. The cursor grows with the zoom by default in every engine ([#253](https://github.com/Maxaubert/Wind/issues/253), [PR #254](https://github.com/Maxaubert/Wind/pull/254)).
7. **Native cursor.** The DWM-drawn pointer with DWM centring ([#369](https://github.com/Maxaubert/Wind/issues/369), [PR #370](https://github.com/Maxaubert/Wind/pull/370)), with the older sprite cursor kept as an A/B fallback ([PR #467](https://github.com/Maxaubert/Wind/pull/467)) and then the legacy path removed ([#384](https://github.com/Maxaubert/Wind/issues/384)).
8. **Rejected visual variants.** Nearest sampling while the zoom level moves and smooth sampling at rest was rejected because the switch was visible. An eased tail that read as shake was also rejected (2026-10-07; see [05-transform-engine.md](architecture/05-transform-engine.md)).
9. **Auto engine removed, owner-tuned defaults.** Max's own tuned settings became the defaults, Transform became the only engine choice and Auto was removed ([#508](https://github.com/Maxaubert/Wind/issues/508)). The Transform scaling default went back to Nearest and the zoom speed to 1.75 ([#510](https://github.com/Maxaubert/Wind/issues/510)).
10. **Settings and UI decisions.** Reorder and rename per Max's direction (`96400b8`, [#221](https://github.com/Maxaubert/Wind/issues/221)). Removing the zoom edge outline ([#251](https://github.com/Maxaubert/Wind/issues/251)). Dark mode only ([#324](https://github.com/Maxaubert/Wind/issues/324)). Pan keys unbound by default, with modifiers on every bind ([#307](https://github.com/Maxaubert/Wind/issues/307)). The Mouse tracking setting ([#490](https://github.com/Maxaubert/Wind/issues/490)).
11. **Profiles.** Named settings profiles in the tray and in Settings ([#178](https://github.com/Maxaubert/Wind/issues/178)).
12. **Edge artefacts found in testing.** A grey line along the left and top edges, seen on his display and fixed ([#244](https://github.com/Maxaubert/Wind/issues/244), [PR #245](https://github.com/Maxaubert/Wind/pull/245)).
13. **Shell panels.** The cursor going under the emoji picker and Win+V, reported from use ([#492](https://github.com/Maxaubert/Wind/issues/492)).
14. **Accessibility.** Acting on a report from a screen-reader (NVDA) user, Max chose the fixes and their scope: the installer ([#513](https://github.com/Maxaubert/Wind/issues/513)), Settings ([#514](https://github.com/Maxaubert/Wind/issues/514)) and the Java Access Bridge crash ([#515](https://github.com/Maxaubert/Wind/issues/515)).
15. **Licence.** Max relicensed Wind from MIT to a proprietary licence after v0.6.1 (`3445f4b`, 2026-09-02), then revised the terms ([#256](https://github.com/Maxaubert/Wind/issues/256)) and added a licence acceptance screen to the installer ([#258](https://github.com/Maxaubert/Wind/issues/258)).

Closed investigations with measurements and "do not retry" conclusions are kept in [docs/history](history/).

## Timestamped proof

Wind's source is timestamped with [OpenTimestamps](https://opentimestamps.org), which anchors a hash
in the Bitcoin blockchain. A proof shows that the hashed content existed no later than the time in
the proof, and nobody, including the owner, can backdate it.

- [docs/provenance](provenance/) holds snapshot records: a commit, its tree, the SHA-256 of its
  source archive, and the `.ots` proof. Because git commit hashes chain, a proof of one commit also
  covers every commit before it. The first snapshot is commit `8566da3` (2026-10-27).
- From the release after 2026-10-27 on, each GitHub release carries `provenance-<version>.txt` and
  its `.ots` proof as release assets. Earlier releases cannot be stamped back to their real dates;
  for them, the git history and GitHub's own records are the evidence.

How to verify is in [docs/provenance/README.md](provenance/README.md).
